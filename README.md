# 报销助手（Reimbursement Assistant）

> 建议 GitHub 仓库标题：**报销助手：订单预处理、发票匹配与截图归档**

面向“电商订单多批次报销”场景的本地化工具。  
核心目标是把报销流程拆成三段可控流水线：

1. 订单预处理（清洗、去重、剔除已报销）
2. 发票匹配与复核（自动匹配 + 人工复核）
3. 截图资料归档（补齐凭证、导出归档包/打印版）

---

## 1. 项目解决的问题

在实际报销中，常见痛点是：

- 订单文件来源多、字段不统一、重复订单多
- 同一笔预处理订单会分批次报销，容易重复报销
- 发票 PDF 数量大，手工比对效率低
- 报销材料（订单截图/支付截图/发票）分散，归档和打印麻烦

本工具通过“分页面分职责”的方式，把问题拆解到每一步，降低误操作和重复劳动。

---

## 2. 功能总览

| 页面 | 主要职责 | 输出结果 |
| --- | --- | --- |
| 订单预处理 | 导入订单、自动去重、导入已报销明细并高亮/移除、手工补录 | 干净可匹配的订单表 |
| 发票匹配与复核 | 解析发票 PDF、自动匹配、标记完美/疑似/无匹配、查看疑似详情 | 匹配结果与导出文件 |
| 截图资料归档 | 管理每条订单的订单截图与支付截图、导出压缩包/打印 PDF | 可直接提交的报销资料包 |

## 3. 页面与分区详细说明（功能 + 动机）

以下按“每个页面的每个主要部分”解释设计动机。

## 3.1 订单预处理页面

### A. 页面抬头与总览卡片

包含四个统计视图：

- 订单总数
- 时间跨度（最早/最晚日期）
- 订单总金额
- 已报销命中数

功能：

- 让用户在操作前先看到当前数据规模和风险面（尤其已报销命中）
- 时间跨度用于快速判断导入范围是否偏移（例如月份导错）

动机：

- 预处理本质是“数据质量关口”，先看全局再做修改能减少后续返工

### B. `1. 数据导入`（左：订单/发票，右：已报销）

#### 左侧「订单与发票」

功能：

- 选择订单文件（支持多文件）
- 选择发票目录
- 设置是否递归扫描发票目录
- 执行“读取并解析订单”
- 自动订单去重（多文件汇总后去重）

动机：

- 将“输入源选择 + 解析”放在同一块，降低路径配置与执行动作的割裂感
- 递归扫描作为同一上下文参数，避免匹配页再重复设置

#### 中间分割线

功能：

- 视觉上分隔“基础数据导入”与“报销历史导入”

动机：

- 这两类输入职责不同：左侧是本次处理对象，右侧是风险约束条件

#### 右侧「导入已报销订单」

功能：

- 支持导入单独报销明细文件（xlsx/xls/csv）
- 支持导入报销平台批量导出的 zip（自动提取明细）
- 导入后生成两类匹配键：
  - 订单号精确匹配
  - 无订单号时的兜底匹配（金额 + 日期 + 店铺）

动机：

- 解决“分批次报销”下最核心风险：同订单重复报销
- zip 自动解包减少用户手工整理成本

### C. 已报销命中提示区

功能：

- 显示已报销总数、当前命中数、来源文件
- 提示是否有“无订单号兜底匹配”命中
- 在表格中高亮已报销订单

动机：

- 报销风控信息必须显著呈现，用户才能决定“保留”还是“移除”

### D. `2. 编辑与缓存`

包含：

- 暂存（手动）
- 自动保存（默认开启）
- 撤回 / 重做（最多 20 步）

功能：

- 所有编辑都支持回退
- 自动保存避免误关页面导致数据丢失
- 自动保存开启时禁用手动暂存，减少认知冲突

动机：

- 预处理是高频改表格动作，稳定性和可恢复性比“速度”更重要

### E. `3. 预处理订单表格`

功能：

- 状态筛选（多选）
- AgGrid 可编辑表格
- 行选择复选框（支持全选）
- 已报销订单高亮

动机：

- 让用户先筛后改，提升批量清理效率
- 复选框选择是批量删除的基础交互

### F. 表格操作按钮组

包含：

- 删除选中
- 清空
- 移除已报销订单
- 开始发票匹配（带自动跳转 + 自动开始匹配）

动机：

- 把“结果性的动作”集中，减少按钮散落导致的误点

### G. `导出预处理结果` 选项卡

功能：

- 导出 CSV
- 导出 Excel（下载或另存）

动机：

- 让预处理结果可外部存档或二次分析

### H. `快速新增订单` 选项卡

功能：

- 使用表单提交，避免输入过程中触发重跑导致 UI 抖动
- 新增订单默认状态为“交易成功”
- 成功添加后自动清空输入框
- 若订单号为空，阻止提交并提示（避免被“无订单号兜底匹配”误识别为已报销）

动机：

- 手工补录是低频但关键动作，稳定输入体验优先
- 明确默认状态可以减少无效字段输入

## 3.2 发票匹配与复核页面

### A. 匹配启动区

功能：

- 一键“开始匹配”
- 从预处理页跳转时可自动触发匹配
- 使用当前预处理表格数据（若为空才回退到文件加载）

动机：

- 保证流水线连贯：预处理完成后无需重复选择/点击

### B. 匹配执行逻辑（后端）

核心规则：

- 综合评分：金额 + 日期 + 店铺
- 按最高分贪心匹配
- 一张发票最多匹配一个订单，一个订单最多匹配一次
- 输出三类状态：
  - 完美匹配
  - 疑似匹配
  - 无匹配

动机：

- 自动化优先，但保留“疑似”给人工复核，避免黑盒误判

### C. 匹配结果汇总卡片

功能：

- 订单数、发票数、匹配数
- 订单总金额、完美匹配金额
- 输出文件名提示

动机：

- 让用户快速评估匹配质量和覆盖率

### D. 结果表格与复核区

功能：

- 状态筛选
- 可视化结果表格（高亮匹配状态）
- 选中“疑似匹配”行可展开疑似发票列表
- 点击疑似发票可直接打开 PDF

动机：

- 把“机器给出的不确定性”聚焦到最小复核闭环

### E. 导出与后续跳转

功能：

- 导出“已匹配订单”CSV/Excel
- 展开查看未匹配发票列表
- 进入截图管理（仅对完美匹配订单）

动机：

- 让下一阶段（截图归档）只处理高确定性的订单，减少噪声

---

## 3.3 截图资料归档页面

### A. 数据来源优先级

加载顺序：

1. 用户上传“已匹配订单文件”
2. 从匹配页跳转带入的完美匹配数据
3. 本地截图暂存恢复

动机：

- 保证不同入口都能继续工作，不强制单一流程

### B. 截图状态总览表

功能：

- 每行显示截图状态：无截图 / 截图不完全 / 有截图
- 点击状态进入对应订单的截图管理

动机：

- 用状态驱动补齐动作，避免遗漏

### C. 截图管理面板（单订单）

每条订单分两类素材：

- 订单截图
- 支付截图

每类支持：

- 从剪贴板添加
- 删除单张
- 清空整类

附加能力：

- 上一个/下一个订单快速切换
- 复制订单号

动机：

- 把“采集、校验、修正”集中在一个局部工作区，提高连续操作效率

### D. 截图页保存机制

功能：

- 自动保存（默认开启）
- 手动暂存（自动保存关闭时可用）
- 下次进入自动恢复

动机：

- 截图是最费时环节，必须保证中途中断可恢复

### E. 导出区

功能：

- 全部导出：生成报销压缩包（发票 + 截图）
- 打印导出：生成可打印 PDF
- 导出文件名包含金额与时间戳

动机：

- 一次导出即可满足“归档提交”和“纸质打印”两种需求

## 3.4 侧栏（默认折叠）

侧栏仅保留“设置”，避免主工作区被路径输入挤占。

包含：

- 配置文件路径
- 列映射（订单号/实付/时间/店铺/商品/状态/商品链接）
- 合并明细开关
- 匹配结果颜色配置（完美/疑似/无匹配）

动机：

- 把“低频配置”与“高频操作”隔离，主路径更专注

## 5. 配置文件详解（`invoice_matcher_config*.json`）

## 5.1 `order_columns`

用于声明订单文件列名映射：

- `order_id`
- `amount`
- `date`
- `vendor`
- `description`
- `status`
- `product_link`

动机：

- 不同平台导出的列名不一致，通过映射减少手改数据

## 5.2 `invoice_patterns`

用于发票文本提取的正则模式：

- `invoice_id`
- `amount`
- `date`
- `vendor`

动机：

- 不同模板发票字段布局不同，支持按项目持续调优识别率

## 5.3 `match_rules`

- `amount_tolerance`: 金额绝对容差
- `amount_tolerance_ratio`: 金额相对容差
- `date_days_tolerance`: 日期容差（天）
- `weights.amount/date/vendor`: 各评分权重
- `min_score`: 最低匹配阈值
- `merge_multi_item_orders`: 是否合并同订单多明细

动机：

- 通过参数化让匹配可解释、可调优，而不是硬编码

## 6. 典型使用流程（推荐）

1. 进入“订单预处理”
2. 左侧导入订单与发票路径，点击“读取并解析订单”
3. 右侧导入已报销明细，确认命中高亮
4. 清理数据（删除选中 / 移除已报销）并确认汇总卡片
5. 点击“开始发票匹配”
6. 在“发票匹配与复核”完成疑似复核、导出匹配结果
7. 进入“截图资料归档”，补齐截图并导出最终材料包

## 7. 运行方式

## 7.1 推荐（Windows）

双击：

- `启动发票匹配助手.bat`

脚本行为：

- 启动前释放 `8501` 端口旧进程
- 启动 Streamlit（文件轮询热更新）
- 浏览器自动打开 `http://localhost:8501`
- 会话断开后快速回收后台进程（`--server.disconnectedSessionTTL 1`）

## 7.2 命令行方式

```powershell
python -m streamlit run streamlit_app.py --server.port 8501
```

---

## 9. 关键设计原则

- **先防错，再提速**：已报销命中高亮与移除优先
- **自动化与人工复核结合**：自动匹配 + 疑似复核
- **状态可恢复**：预处理与截图均支持本地暂存恢复
- **配置可解释**：列映射与匹配规则集中管理
